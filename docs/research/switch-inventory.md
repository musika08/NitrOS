# NitrOS switch inventory (candidate catalog)

Date: 2026-10-24. Built only from the spec (`docs/superpowers/specs/2026-10-24-nitros-design.md`) and the six research files in this folder. Nothing here was tested on a PC. Every row is a candidate; the measurement run (spec section 7) decides what finally ships.

## How to read this file

**Groups.** The spec's seven groups, with `big-parts` split into `edge-onedrive`, `windows-ai`, `xbox`, `security-updates` and a remaining `big-parts`. The vendor GPU panel switch sits in `manufacturer-addons`. Game Bar background recording sits in `gaming-settings` (spec group 6) even though the card row is near the Xbox rows.

**Cards** column is Recommended / Gamer / Streamer / Max Lean, using Core's `CardDefault` values: `on` = the switch is ticked (the thing is removed or turned off), `off` = not ticked (kept or "unchanged"), `pending` = "decided by measurement". A `*` after the cards means the spec does not state them; the value is my proposal and the switch is listed in the "Card defaults not derived from the spec" section at the end.

**Actions** are written in Core's field order, one call per action, separated by `;`. Mapping to JSON (`src/NitrOS.Core/Model/Actions.cs`):

| Written here | JSON |
|---|---|
| `registry.set(HIVE, key, name, kind, data)` | `{"type":"registry.set","hive":..,"key":..,"name":..,"kind":..,"data":..}` (double every backslash in JSON) |
| `service.start(service, start)` | `{"type":"service.start","service":..,"start":..}` |
| `task.disable(path)` | `{"type":"task.disable","path":..}` |
| `appx.remove(name)` | `{"type":"appx.remove","name":..}` |
| `capability.remove(name)` | `{"type":"capability.remove","name":..}` |
| `feature.disable(name)` | `{"type":"feature.disable","name":..}` |
| `package.remove(pattern)` | `{"type":"package.remove","pattern":..}` |
| `file.remove(path)` | `{"type":"file.remove","path":..}` |
| `power.set(subgroup, setting, ac, dc)` | `{"type":"power.set","subgroup":..,"setting":..,"ac":..,"dc":..}` |

Kinds and start types use the camelCase the existing catalog uses (`dword`, `string`, `disabled`, `manual`). Hives are `HKLM` / `HKCU` as in `catalog/privacy-ads.json`.

**Image column.** `= live` means the same actions applied to the mounted image: `HKLM\SOFTWARE` and `HKLM\SYSTEM` go to the offline SOFTWARE/SYSTEM hives (the Image engine must map `CurrentControlSet` to the image's active control set, as Tiny11's WinUI app does), `HKCU` goes to the default-user hive `Users\Default\ntuser.dat`, services become offline `Start` values, `appx.remove` removes the provisioned package. Spec 5.3: never write protected user keys offline (Tiny11 issues #640/#647); none of the rows below write `SearchSettings`.

**File paths** use `%SystemRoot%`, `%ProgramFiles(x86)%`; the Image engine maps them under the mount root.

**reversible** is about Tune mode (spec 5.1). Every `appx.remove`, `file.remove`, `package.remove` and uninstall is `false` (gets the "Can't be undone without reinstalling" badge). winutil re-registers a removed app from its local manifest (`Install-WinUtilAPPX.ps1`); if Core wants app removals to count as reversible, that method must be proven first.

**cut** column: `mem` = likely a real memory and process cut (per web-evidence.md / ally-x-inventory.md); `proc` = process count or periodic CPU/disk only; `small` = real but small; `none` = no idle effect expected (disk, privacy or looks only); `priv` = privacy only; `looks` = interface only.

**Markers.** `UNVERIFIED:` an identifier or value is missing from the research or the research rows disagree. `NEEDS ACTION TYPE:` Core's 10 types cannot express it; see "Proposed new action types". Missing items (an app not installed, a service that does not exist on this build) must be a no-op, not a failure: many rows target things that exist only on some builds (Recall, WSAIFabricSvc, Skype, Cortana, Mixed Reality Portal).

**requires.** Spec 5.1: "switch ids that must stay kept for this one to work". Almost no rows need it. The real dependencies are the other way round ("removing the Store breaks the kept Xbox app"); Core's `requires` cannot express that, see "Spec contradictions and gaps" item 7. Where I give a `requires` it means: these switch ids must stay unticked.

Source shorthand: `wu` = winutil-tweaks.md, `wh` = winhance-settings.md, `t11` = tiny11-removals.md, `web` = web-evidence.md, `ally` = ally-x-inventory.md, `dev` = device-updates.md, `spec` = the design spec.

## Considered and left out

- **Not-shipped list (spec s2):** SysMain and Prefetch, memory compression, pagefile, timer resolution, Nagle / TcpAckFrequency / TCPNoDelay, NetworkThrottlingIndex / SystemResponsiveness (and the MMCSS Games Priority / GPU Priority / Scheduling Category values in the same key), Win32PrioritySeparation, MSI mode, MPO (`OverlayTestMode`, `DisableOverlays`, `OverlayMinFPS`), core parking (`CPMINCORES`/`CPMAXCORES`), HPET and bcdedit timer tweaks, Spectre/Meltdown, Office Click-to-Run (ally suggests a switch; the spec wins), touch keyboard service and TextInputHost rename, Error Reporting (`WerSvc`, policy `Windows Error Reporting\Disabled`, task `QueueReporting`, and winutil's Telemetry tweak's WerSvc part).
- **Harmful or against the spec:** Ultimate Performance plan on handhelds; S3 sleep; hibernation off; power throttling off; automatic maintenance off (`MaintenanceDisabled`, stops trim); all notifications off (hides handheld prompts); Game Bar controller button off (`UseNexusForGameBarEnabled`); hardware-check bypass and local-account bypass (t11 1e #48, #49; TPM rule); WinSxS pruning, `/ResetBase`, CBS language and LA57 packages (no servicing after); Windows Update service key deletion and localhost WSUS (t11 PS-C); `SearchOrderConfig`=0 and `DisableCoInstallers`=1; Smart App Control, UAC, BitLocker changes (spec s11 lists Smart App Control as a question to verify, not a switch); IPv6 / Teredo (wu: values conflict; may break games).
- **Disk only, no idle effect:** legacy capabilities (`Microsoft.Windows.WordPad`, `App.StepsRecorder`, `MathRecognizer`, `Media.WindowsMediaPlayer`, `Microsoft.Windows.PowerShell.ISE`, `Browser.InternetExplorer`, `Microsoft.Windows.Wallpaper.Extended`, `OpenSSH.*`), Windows AI workload packages (`WindowsWorkload.*`, wh "none (on-disk only)"), Copilot+ packages with truncated names (wh), reserved storage, Storage Sense, temp cleanup. They could return as ISO-size options; spec s2 asks for memory or load gains.
- **Looks only, not in the spec:** visual effects, dark mode, taskbar alignment, context menu, Explorer options, lock screen, accessibility hotkeys.
- **Not in v1 scope:** DNS changers, O&O ShutUp10++, Brave debloat, Adobe hosts block, Razer and Logitech install blocks (could seed `other-oem-apps-remove` later).

## Proposed new action types

| Name | Fields | What Tune mode would do | Undo | Image mode |
|---|---|---|---|---|
| `program.uninstall` | `match` (display name and publisher, or uninstall key name), `args` (silent switches, optional), `signer` (expected publisher, optional), `protect` (folders to shield, optional, as winutil does for OneDrive) | Finds the program's uninstall entry under `...\CurrentVersion\Uninstall` (both views), checks the signer, runs its quiet uninstaller with `args`, waits, then removes leftover uninstall entries (spec 5.3) | Not reversible; record name, version and the maker's download page so the Review and Undo screens can say how to reinstall | No (Win32 programs are not in the ISO; Edge and OneDrive use `file.remove` there) |
| `startup.disable` | `source` (`run` with hive and value name, `startupFolder` with file name, `appxTask` with package family and task id, `task` with path), `name` (exact or wildcard) | Turns the entry off the way Task Manager's Startup tab does, without deleting it | Turn it back on from the saved original state | Partly: only `run` entries in the default-user hive (e.g. `OneDriveSetup`); others are created after install |
| `registry.delete` | `hive`, `key`, `name` (optional; absent = whole key) | Exports the key or value to the backup folder, then deletes it (Edge uninstall entries, Outlook/Dev Home orchestrator keys, ContentDeliveryManager subkeys, OneDriveSetup Run value) | Re-import the export | Yes (offline hives) |
| `reinstall.block` | `kind` (`oemApp`), `match` (package family names, device hardware ids or maker name), `allowDrivers` (always true) | Blocks the path Windows Update and firmware use to reinstall maker apps while drivers and firmware keep updating; mechanism to be found per spec s11 ("how Windows Update reinstalls manufacturer apps, and how to block it") | Remove the block | Yes, if the mechanism is a policy or key |
| `power.scheme` | `scheme` (GUID), `fallback` (GUID, optional) | Makes that power plan active (e.g. High performance `8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c`); refuses `e9a42b02-...` on battery devices | Re-activate the previously active plan GUID saved in the backup | No (needs first-logon) |
| `launch.atLogon` | `program` (path or app id), `args`, `when` (`logon`), `replaceShell` (false) | Adds a per-user start-up entry for Steam Big Picture or Playnite full screen; only if the program is installed | Remove the entry | No (the programs are not in the ISO) |
| `appx.removeSystem` | `name` | For system packages that refuse normal removal (`MicrosoftWindows.Client.CoreAI`): resolves the full name, writes the `AppxAllUserStore\EndOfLife\<SID>\<PackageFullName>` key as winutil does, then removes it | Not reversible (winutil says so) | Only the provisioned copy, if any |
| computed `data` for `registry.set` (extension, not a new type) | a token such as `{installedMemoryKB}` in `data` | Lets `svchost-grouping-on` write the installed memory in KB, as winutil does | Normal registry undo | Needs the target PC's memory, unknown at build time: either a large fixed value (untested) or a first-logon step |

## Spec contradictions and gaps

1. **Max Lean Windows Update off vs Device updates.** Spec 5.4 makes Windows Update layer 1 of Device updates and says it "stays allowed for drivers and firmware"; Max Lean turns Windows Update off, so that layer and Vanguard's on-demand mode (web) stop working.
2. **"Only ship with a real gain" vs group 6.** Mouse acceleration has no load effect (web "depends"), and every "network delay" tweak is on the Not-shipped list, so group 6's "network delay" has nothing to ship. Same tension for the svchost threshold (web: "none for real RAM", cosmetic process count) and the disk-only recovery removal.
3. **Virtualization off on Gamer/Streamer vs "VBS as the user has them".** Web says never disable Hyper-V or the hypervisor platform by default; the spec turns VMP and Hyper-V off on Gamer and Streamer while promising anti-cheat games keep working. Also, spec 7 runs the measuring VM on Hyper-V on the owner's PC; applying Gamer to that PC would break it.
4. **Start-up cleanup removes OneDrive setup on Recommended, which keeps OneDrive.**
5. **Bluetooth is listed as a removable big part (group 3) but kept on every card and in the health check.** No switch proposed.
6. **"Camera and capture parts" is not defined.** Interpreted as the Camera app and Snipping Tool.
7. **`requires` can't express the real dependencies.** The danger is "removing the Store or Gaming Services breaks the kept Xbox app" (a removal switch hurting something kept), but `requires` only says "this switch needs that switch unticked". Core needs a second relation (for example `breaksIfKept` or a "kept item needs" list) or these stay as plain `breaks` text.
8. **Reversible apps.** Spec 6 says Tune mode turns things off rather than deleting, but most of the catalog is `appx.remove`, which spec 5.1 badges "Can't be undone without reinstalling" with a second confirm, even on Recommended.
9. **Steam Big Picture is "the replacement" for Xbox home in Max Lean (s3) but "off unless chosen" (s2).** Kept off on every card.
10. **Search indexing off does not remove `SearchHost`** (175 MB on the Ally); the card's saving will be smaller than the inventory suggests.
