# NitrOS switch inventory (frozen catalog source)

Date: 2026-10-24. First built from the spec (`docs/superpowers/specs/2026-10-24-nitros-design.md`) and the six research files in this folder (commit `7f029c4`). **Frozen on 2026-10-24 (plan 2, task 2)**: every identifier was checked against the owner's ROG Xbox Ally X (Windows 11 Pro 26H2, build 26300.9711) and primary sources. Each row now carries a `status`: `VERIFIED` or `DROPPED: <reason>`. The checks, counts and every drop are in `identifier-checks.md`. Tasks 3 to 7 copy only the `VERIFIED` rows. The measurement run (spec section 7) still decides what finally ships.

## How to read this file

**Status.** `VERIFIED` = every identifier the row uses was found on this PC with the exact name, or stated by a primary source (Windows' own policy templates in `C:\Windows\PolicyDefinitions` on build 26300, Microsoft Learn, the vendor's own pages or source), or agreed by both winutil and Winhance in the research files. Values that failed the check were corrected or removed from the row (the `source` cell says which). `DROPPED: <reason>` = at least one identifier the row depends on could not be checked; the row is not in the catalog. Dropped rows are kept short; their original text is in git (`7f029c4`).

**Groups.** The spec's seven groups, with `big-parts` split into `edge-onedrive`, `windows-ai`, `xbox`, `security-updates` and a remaining `big-parts`. The vendor GPU panel switch sits in `manufacturer-addons`. Game Bar background recording sits in `gaming-settings` (spec group 6).

**Cards** column is Recommended / Gamer / Streamer / Max Lean, using Core's `CardDefault` values: `on` = the switch is ticked (the thing is removed or turned off), `off` = not ticked (kept or "unchanged"), `pending` = "decided by measurement". The proposals in "Card defaults not derived from the spec" were accepted by the owner on 2026-10-24 (except `virtualization-off`, set to off/off/off/on).

**Actions** are written in Core's field order, one call per action, separated by `;`. Mapping to JSON (`src/NitrOS.Core/Model/Actions.cs`):

| Written here | JSON |
|---|---|
| `registry.set(HIVE, key, name, kind, data)` | `{"type":"registry.set","hive":..,"key":..,"name":..,"kind":..,"data":..}` (double every backslash in JSON) |
| `service.start(service, start)` | `{"type":"service.start","service":..,"start":..}` |
| `task.disable(path)` | `{"type":"task.disable","path":..}` |
| `appx.remove(name)` | `{"type":"appx.remove","name":..}` |
| `capability.remove(name)` | `{"type":"capability.remove","name":..}` |
| `feature.disable(name)` | `{"type":"feature.disable","name":..}` |
| `package.remove(pattern)` | `{"type":"package.remove","pattern":..}` |
| `file.remove(path)` | `{"type":"file.remove","path":..}` |
| `power.set(subgroup, setting, ac, dc)` | `{"type":"power.set","subgroup":..,"setting":..,"ac":..,"dc":..}` |
| `program.uninstall(displayName, publisher, args?)` | `{"type":"program.uninstall","displayName":..,"publisher":..,"args":..}` (omit `args` when not given) |
| `startup.disable(source, name, hive?)` | `{"type":"startup.disable","source":..,"name":..,"hive":..}` (`source` is `run`, `startup-folder`, `appx-task` or `task`; `hive` only for `run`) |
| `registry.delete(hive, key, name?)` | `{"type":"registry.delete","hive":..,"key":..,"name":..}` (omit `name` to delete the whole key) |
| `power.scheme(scheme)` | `{"type":"power.scheme","scheme":..}` |
| `launch.at-logon(program, args?)` | `{"type":"launch.at-logon","program":..,"args":..}` |

Kinds and start types use the camelCase the existing catalog uses (`dword`, `string`, `disabled`, `manual`). Hives are `HKLM` / `HKCU` as in `catalog/privacy-ads.json`. Power settings use GUIDs (as `powercfg /qh` prints them on this PC), not aliases. An `appx-task` start-up name is `<PackageFamilyName>!<TaskId>`, as the task is stored under `HKCU\Software\Classes\Local Settings\Software\Microsoft\Windows\CurrentVersion\AppModel\SystemAppData\<PackageFamilyName>\<TaskId>`. A `*` in a `startup.disable` or `program.uninstall` name is a wildcard.

**Image column.** `= live` means the same actions applied to the mounted image: `HKLM\SOFTWARE` and `HKLM\SYSTEM` go to the offline SOFTWARE/SYSTEM hives (the Image engine must map `CurrentControlSet` to the image's active control set, as Tiny11's WinUI app does), `HKCU` goes to the default-user hive `Users\Default\ntuser.dat`, services become offline `Start` values, `appx.remove` removes the provisioned package. Spec 5.3: never write protected user keys offline (Tiny11 issues #640/#647); none of the rows below write `SearchSettings`.

**File paths** use `%SystemRoot%`, `%ProgramFiles(x86)%`, `%LOCALAPPDATA%`; the engines expand them (the Image engine maps them under the mount root).

**reversible** is about Tune mode (spec 5.1). Every `appx.remove`, `file.remove`, `package.remove` and `program.uninstall` row is `false` (gets the "Can't be undone without reinstalling" badge).

**requires** (spec 5.1): if switch S lists T, the feature S removes depends on the feature T removes. Core warns when T is ticked while S is not ("Microsoft Store is needed by Xbox app, which you are keeping"). Only two rows list anything: `xbox-app-remove` (the Store, Gaming Services and Xbox sign-in switches) and `edge-game-assist-remove` (the Edge switch); Game Bar recording lists nothing.

**cut** column: `mem` = likely a real memory and process cut; `proc` = process count or periodic CPU/disk only; `small` = real but small; `none` = no idle effect expected; `priv` = privacy only; `looks` = interface only.

**Missing items** (an app not installed, a service that does not exist on this build) are a no-op for the PC tuner, not a failure.

Evidence shorthand in the `source` column: `pc:appx` (Get-AppxPackage -AllUsers on this PC), `pc:deprov` (listed under `AppxAllUserStore\Deprovisioned` on this PC, i.e. it shipped with this build and was removed), `pc:svc`, `pc:task`, `pc:feature`, `pc:reg` (value or key read on this PC), `pc:uninstall`, `pc:run`, `pc:startup-task`, `pc:powercfg`, `admx:<file>` (Windows' own template in `C:\Windows\PolicyDefinitions` on build 26300), `learn:<page>` (Microsoft Learn), `wu+wh` (winutil and Winhance agree in the research files), `vendor:<...>`. Research shorthand: `wu` = winutil-tweaks.md, `wh` = winhance-settings.md, `t11` = tiny11-removals.md, `web` = web-evidence.md, `ally` = ally-x-inventory.md, `dev` = device-updates.md, `spec` = the design spec.

## Spec contradictions and gaps

1. **Max Lean Windows Update off vs Device updates.** Resolved 2026-10-24: `windows-update-auto-off` stops only automatic downloads and installs.
2. **"Only ship with a real gain" vs group 6.** Mouse acceleration has no load effect, every "network delay" tweak is on the Not-shipped list, and the svchost threshold and recovery removal are small or disk-only. Open; measurement decides.
3. **Virtualization off on Gamer/Streamer.** Resolved 2026-10-24: off/off/off/on.
4. **Start-up cleanup removes OneDrive setup on Recommended, which keeps OneDrive.** Open.
5. **Bluetooth.** Resolved 2026-10-24: `bluetooth-off` exists and is off on every card.
6. **"Camera and capture parts" is not defined.** Interpreted as the Camera app and Snipping Tool.
7. **`requires` direction.** Resolved: the spec now defines `requires` as "the feature S removes depends on the feature T removes", so `xbox-app-remove` lists `store-remove`, `gaming-services-remove` and `xbox-sign-in-remove`, and `edge-game-assist-remove` lists `edge-remove` (controller ruling, task 2 review).
8. **Reversible apps.** Most of the catalog is `appx.remove`, badged "Can't be undone without reinstalling", even on Recommended. Open.
9. **Steam Big Picture is "the replacement" for Xbox home in Max Lean (s3) but "off unless chosen" (s2).** Kept off on every card.
10. **Search indexing off does not remove `SearchHost`** (175 MB on the Ally); the card's saving will be smaller.
