# NitrOS Plan 5: App Screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `NitrOS.App`, the WinUI 3 window with every screen in spec section 4, on top of a separate, testable `NitrOS.App.Logic` that holds the view models, navigation and the glue to Core and Live. Tune mode works end to end (Start, Cards, Switches, Review, Working, Done) through plan 3's `TuneEngine`. Add Undo, the drift check on open, the health check after restart, the optional "check after updates" task, the "myths we tested" help, and seams for the ISO builder (plan 6), Device updates (plan 7) and Max Lean's "Add Xbox back" (proven in plan 4).

**Architecture:** Three layers. `NitrOS.App.Logic` (no WinUI reference) has the view models (`ObservableObject` from CommunityToolkit.Mvvm), a `Navigator` keyed by `ScreenKey`, small ports for everything outside (runner, undo, drift, health, dialogs, restart) and the real implementations of those ports, which call Core and Live and nothing else. `NitrOS.App` is thin XAML pages bound to those view models, plus a `PageMap` from `ScreenKey` to page type. `NitrOS.Live` gains a few read-mostly adapters the app needs (memory and process meter, Windows version, restart, the one-off after-restart launch, the optional logon task) and two API fixes from the plan 3 review. View models are unit-tested against fakes. Anything that changes the PC runs only in the VM lane.

**Tech Stack:** .NET 10 (SDK 10.0.402), C#. `NitrOS.App`: WinUI 3 from Windows App SDK `Microsoft.WindowsAppSDK` 2.5.1 (stable, released 2026-09-16), unpackaged and self-contained, `net10.0-windows10.0.19041.0`, `win-x64`. `NitrOS.App.Logic`: `net10.0-windows10.0.19041.0` (it references Live), `CommunityToolkit.Mvvm` 8.4.2. Tests: xUnit v3 as before.

**Spec:** `docs/superpowers/specs/2026-10-24-nitros-design.md` (sections 1, 2, 3, 4, 5, 6, 7). Also `docs/research/notes-for-later-plans.md` (Plan 5 section) and `docs/superpowers/plans/2026-10-25-nitros-03-tuner.md`.

**This is plan 5 of 7.** Plans 1 (Core), 2 (catalog) and 3 (PC tuner) are merged. Plan 4 (measurement VM) fills the catalog's `measured` fields and runs the VM-lane tests. Later: 6 ISO builder (implements this plan's `IRunner` for ISO runs), 7 device updates (registers the Device updates screen).

## Rulings (choices the spec left open)

1. **Unpackaged, self-contained.** Packaged (MSIX) apps need the restricted `allowElevation` capability and a signing certificate to run as administrator, and NitrOS has no Store or background need. Unpackaged gives a plain folder with `NitrOS.App.exe`, the catalog and the Windows App SDK files, xcopy-deployable. x64 only in version 1 (the Ally X is x64).
2. **The whole app runs elevated** (`requireAdministrator` in `app.manifest`). Reading the secured journal folder, the drift check, Tune, Undo, ISO building (DISM) and device installs all need administrator rights, so a non-elevated shell plus an elevated helper would add a second process and a progress channel for nothing. The cost is one UAC prompt when NitrOS opens.
3. **The secured folder is made only by a run.** `%ProgramData%\NitrOS\backups` and `%ProgramData%\NitrOS\app` are created only inside `TuneRunner` and `LiveUndoService` after `SessionGuard.Check` passes and the user pressed Go or Undo. Everything else (journal list, drift, health, state) uses a new read-only `BackupFolder.Check`, which never creates anything. `JournalAccess` also refuses to ensure the folder when `ISessionFacts.IsElevated` is false.
4. **Post-restart health check:** two routes, no resident process. (a) After a run that changed anything, NitrOS writes one HKLM `RunOnce` value `NitrOS.HealthCheck` = `"<exe>" --after-restart`. Windows consumes it at the next administrator sign-in. (b) Whenever NitrOS opens normally and a health check is still pending since a restart, it runs the check first. Route (a) is best effort: if the HKLM key cannot be written (the owner's PC refuses some `HKLM\SOFTWARE` writes, spec 11) or the VM check shows it does not elevate on current Windows, route (b) alone remains.
5. **"Check after updates"** is a scheduled task `\NitrOS\CheckAfterUpdates`, off by default, turned on in Settings. It triggers at the signed-in user's logon with `HighestAvailable`, runs `"<exe>" --after-update` with a 10-minute limit, and exits. In that mode NitrOS compares the Windows build and revision (`CurrentBuildNumber.UBR`) with the last one it checked; unchanged means exit at once without a window; changed means run the drift check and open a window only if something drifted.
6. **Drift on open** checks every journal of this account, newest first, and merges the drifted switches. "Turn them off again" builds `Selection.FromIds` of exactly those switches and goes through Review and Go like any run. Nothing is changed without Go.
7. **Undo screen:** lists this account's runs newest first; each run expands to its switches with a per-switch Undo. "Undo everything" undoes every run of this account, newest first, after one confirm. Journals of other accounts are not listed; a line says how many are hidden.
8. **Irreversible switches:** Review shows one grouped warning ("29 of these changes can't be undone without reinstalling") with the names collapsed underneath. Go asks one second confirm for all of them together, never one per switch.
9. **Before/after on Done:** memory in use and process count, sampled three times one second apart (middle value kept), just before the run and just after it. The health check after restart samples again and shows "after restart" against the same "before". Memory text always says "available to Windows" and adds the amount set aside for graphics and hardware when it is 512 MB or more.
10. **Input and look:** full keyboard and gamepad navigation with XY focus on every page; buttons and rows at least 48 effective pixels tall (our own choice, comfortable for a thumb on a 7-inch 1080p screen); one column, at most 960 effective pixels wide; layouts checked at 1280x720 effective pixels. WinUI default styles and theme, `MicaBackdrop` on the window, nothing else. The focus visual is the WinUI default.
11. **Gamepad:** if the verify step shows WinUI 3 desktop windows do not get D-pad and A/B natively, a small `GamepadFocusBridge` in `NitrOS.App` polls `Windows.Gaming.Input.Gamepad` only while the window is active and maps D-pad/left stick to focus moves, A to invoke, B to Back. Reading controller input is UI input, not a change to Windows, so it stays in the App project.
12. **Closing during a run:** the window refuses to close while a run is in progress and says to press Cancel on the Working screen first.
13. **Device updates and Add Xbox back are hidden or disabled until their plans land:** the Device updates entry on Start is shown disabled with "Device updates comes in a later NitrOS update." until a screen is registered for `ScreenKeys.DeviceUpdates`. "Add Xbox back" is hidden until an `IXboxRestorer` reports `IsAvailable`.
14. **ISO path in plan 5:** Start's "Build a slim ISO" goes through Cards, Switches and Review in `BuildIso` mode, but Go stays disabled with "Building a slim ISO comes in a later NitrOS update. You can look through the cards and switches now; nothing is built." Choosing the source ISO and output file is plan 6's screen.
15. **No MVVM source generators.** View models derive from `ObservableObject` and use `SetProperty`, `RelayCommand` and `AsyncRelayCommand` directly. This keeps `TreatWarningsAsErrors` clear of generator diagnostics.

## Global Constraints

- Plan 1 to 3 constraints still hold: SDK pin in `global.json`, `Nullable`, `TreatWarningsAsErrors`, xUnit v3 Exe test projects, no `using Xunit;` (global using in the test `.csproj`), namespaces mirror folders. `NitrOS.Core` stays free of Windows APIs.
- **Commits carry no Claude attribution** (owner rule, 2026-10-24): no `Co-Authored-By` trailer, no "Generated with" line. Before committing, `git config user.email` must print `225994527+musika08@users.noreply.github.com`. Each commit stages only its task's paths.
- **Nothing in this plan changes the owner's real Windows** (an ASUS ROG Xbox Ally X, Windows 11 build 26300). Tests on the owner's PC only read, or write to sandbox targets they create and remove themselves (as in plan 3: `HKCU\Software\NitrOS.Tests`, task folder `\NitrOS.Tests\`, the test's own temp folder). Anything that changes the system carries `[Trait("Lane","Vm")]` and `Assert.SkipUnless(Environment.GetEnvironmentVariable("NITROS_VM") == "1", "VM lane only")`. That includes every test that applies or undoes switches for real, restarts, writes `RunOnce`, registers a scheduled task outside `\NitrOS.Tests\`, or creates `%ProgramData%\NitrOS`.
- Any step that needs admin on the owner's PC is a marked **OWNER CHECKPOINT**. The controller runs it through a UAC-elevated `.ps1` that writes its output to `%USERPROFILE%`. A restart needs the owner's explicit OK first. Never change Defender settings or permissions (ACLs) on the owner's PC.
- **The app never touches Windows directly.** `NitrOS.App` (XAML) and `NitrOS.App.Logic` reach Windows only through Core and Live types. The single exception is controller input in `GamepadFocusBridge` (ruling 11). `NitrOS.App.Logic` has no reference to any WinUI or Windows App SDK assembly; a test enforces it.
- **Nothing happens until Go.** No view model calls a runner, undo, restart, task registration or state write from its constructor, from `OnShown`, or from a toggle. Only a user command does, and only after the confirms this plan names.
- **Only this account's journals.** Every list of journals is filtered to `RunJournal.UserSid` equal (case-insensitive) to `ISessionFacts.ProcessUserSid`.
- Do not guess APIs, versions, package names or flags. Where a task says "verify first", do it and write the source and date into the task's commit message body; if it fails, stop and report NEEDS_CONTEXT.
- Plain English in every on-screen text: short sentences, no em-dashes, no emojis. On-screen texts the tests assert live in `src/NitrOS.App.Logic/Texts.cs` as constants.

## Review Focus

1. Review changes nothing until Go, and Go asks once for all irreversible switches together. (Task 6, `Review_NothingHappensUntilGo`, `Review_GoAsksOnceForAllIrreversible`)
2. The secured folder is never created by listing, drift, health or a refused run. (Task 2, `BackupFolder_CheckNeverCreates`; Task 6, `TuneRunner_RefusedSessionCreatesNothing`, `JournalAccess_ListDoesNotEnsureFolder`)
3. While a run holds the lock, here or in another process, every change button is disabled. (Task 4, `RunGate_DisablesChangeCommandsWhileBusy`; Task 6, `Review_GoDisabledWhileLockHeldElsewhere`)
4. Undo offers only this account's journals, and `JournalOwnerException` still shows a plain message if one slips through. (Task 8, `Undo_ListsOnlyThisAccountsJournals`, `Undo_OwnerExceptionShowsMessage`)
5. The drift check asks before turning anything off again, and reports the switches it could not check. (Task 9, `Drift_NeverRunsWithoutGo`, `Drift_ShowsErrorsFromReport`)
6. ISO mode never shows "card partly applied" and its Go is disabled with a reason. (Task 5, `Cards_IsoModeNeverShowsPartlyApplied`; Task 6, `Review_IsoGoDisabledWithReason`)
