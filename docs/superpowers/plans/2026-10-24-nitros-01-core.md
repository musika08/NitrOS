# NitrOS Plan 1: Switch List and Engine (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `NitrOS.Core`: the switch-list file format, its loader and checker, card selection with device and mode rules, warnings, and memory totals. It is pure logic with no changes to Windows, fully covered by tests.

**Architecture:** One class library (`src/NitrOS.Core`) plus one test project (`tests/NitrOS.Core.Tests`). The switch list lives as JSON files in `catalog/`, one file per group plus `cards.json`. Core parses them into immutable records, checks them, and answers three questions for the later parts (app, PC tuner, ISO builder): which switches are on, what warnings apply, and what the totals are.

**Tech Stack:** .NET 10 LTS (SDK 10.0.402), C#, System.Text.Json (in-box), xUnit v3 4.0.2, Microsoft.NET.Test.Sdk 18.11.0, xunit.runner.visualstudio 4.0.1.

**Spec:** `docs/superpowers/specs/2026-10-24-nitros-design.md` (sections 3, 5.1, 5.2 and the cards table). Read it before starting.

**This is plan 1 of 7.** Later plans, each written after the previous one lands:
2. Catalog content (every group, from `docs/research/`).
3. PC tuner (`NitrOS.Live`: apply, backup, undo, health check, device detection).
4. Measurement harness (Hyper-V test machine).
5. App screens (`NitrOS.App`, WinUI 3).
6. ISO builder (`NitrOS.Image`).
7. Device updates (`NitrOS.Updates`).

## Global Constraints

- SDK pinned by `global.json`: version `10.0.402`, `rollForward` `latestFeature`. Target framework `net10.0`.
- `NitrOS.Core` uses no Windows-only APIs and no NuGet runtime packages. It never reads the registry, services or the live system.
- `Nullable` enabled and `TreatWarningsAsErrors` true in all projects.
- Switch JSON: camelCase property names; enum values in kebab-case (`max-lean`, `automatic-delayed`); unknown properties are an error.
- A switch's `description` is one plain line, at most 120 characters.
- Commits use the repo's configured identity, and every commit message ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Code borrowed from ChrisTitusTech/winutil (MIT) is credited in `NOTICE.md`. Nothing is copied from Winhance or Tiny11 Builder.
- The xUnit v3 test project is an executable (`<OutputType>Exe</OutputType>`).

## Review Focus

1. A catalog file with broken JSON or an unknown action `type`: load returns an error naming the file and line, keeps checking the other files, and never throws. (Task 3, `Load_ReportsBrokenJsonWithFileAndLine`, `Load_ReportsUnknownActionType`)
2. The same switch id in two group files: one error naming both files. (Task 4, `DuplicateId_NamesBothFiles`)
3. Toggling a switch that is unavailable in this mode or protected on this device: refused with the reason, never silently turned on. (Task 5, `Toggle_RefusesUnavailableWithReason`)
4. Removing something a kept feature needs, then removing the dependent too: the warning appears, then disappears. (Task 6, `Dependency_WarningClearsWhenDependentAlsoRemoved`)
5. Totals with some selected switches unmeasured: shown as an estimate with an unmeasured count, never as a silent 0. (Task 7, `Totals_CountsUnmeasuredSwitches`)

### Task 6: Warnings

**Files:**
- Create: `src/NitrOS.Core/Selection/WarningEngine.cs`, `tests/NitrOS.Core.Tests/Selection/WarningEngineTests.cs`

**Interfaces:**
- Consumes: `Selection` (Task 5).
- Produces:
  - `enum WarningKind { Breaks, Dependency, Irreversible }`
  - `record Warning(WarningKind Kind, string SwitchId, string? RelatedId, string Message)`
  - `static class WarningEngine { IReadOnlyList<Warning> For(Selection selection) }`. Order: catalog switch order; within a switch, Breaks, then Dependency, then Irreversible.

What `requires` means: if switch S lists T in `requires`, the feature S removes depends on the feature T removes. A Dependency warning fires when T is on and S is off (S's feature is kept but its dependency is removed). Warning fields: `SwitchId = T.Id`, `RelatedId = S.Id`, and `Message = $"{T.Feature} is needed by {S.Feature}, which you are keeping."`.

Breaks: each sentence in an on switch's `breaks` list gives one warning, with `Message` = the sentence.
Irreversible: an on switch with `reversible: false` in TunePc only gives `Message = "Can't be undone without reinstalling."`.
